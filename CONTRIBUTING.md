## Why this repository does not merge external code

This repository operates under **C5 (Human Writes Zero Code)** — all implementation code is generated by AI under direction of the human PM (Yuta Yokoi). The whole point of the artifact is that **every line can be traced to that arrangement**; merging code written by a third party would not be forbidden so much as it would **destroy the measurement**, in the way that adding a second heat source ruins a calorimetry experiment.

So this is not a permission you lack. **You may take this repository and do anything with it, including running your own version that accepts contributions from anyone.** It is only this particular copy, kept as evidence, that stays single-authorship. Nothing stops you from opening a pull request either — it simply will not be merged here, and it costs you nothing to try.

The seven hard constraints are:
- **C1 Boring Technology** — zero external frameworks/libraries in the shipped site (no React/Vue/Svelte/Tailwind/Bootstrap/Framer Motion)
- **C2 IIFE** — main logic lives inside IIFEs; no global-scope pollution
- **C3 ErrorBoundary** — View Transition API errors handled by an explicit error boundary
- **C4 No Framework Re-proposal** — frameworks are permanently rejected
- **C5 Human Writes Zero Code** — human writes design + prompts only; all implementation code is AI-generated
- **C6 AIO Integrity** — AIO published layer (`llms*.txt`, `.well-known/*`, JSON-LD, binary metadata) must stay true, non-fabricated, and coherent across every surface, with the digest chain regenerated on every change (**承認ゲートではない** — 2026-08-23 是正)
- **C7 KARTE CDN SRI Non-Application** — no SRI on KARTE CDN

See `AI2AI.md` (canon) and `CLAUDE.md` (router) for the full architecture.

## How AI agents (Claude Code / sub-agents) contribute

If you are a Claude Code instance, sub-agent, or other AI implementer working under the human PM's direction:
1. Read `CLAUDE.md` §0 (read order), `AI2AI.md` (canon), `llms-full.txt` (ground truth) in that order before editing.
2. Follow the discover → document → systematize (machine-enforced Check) → verify → deliver discipline (CLAUDE.md §5).
3. Use the `repo-auditor` / `check-author` / `aio-guardian` sub-agents per their `description` fields.
4. Never use `git add .` / `-A` / `--all` (denied by `.claude/settings.json`).
5. Never bypass `--no-verify` or skip the consistency check (`check_repository_consistency.py`).
6. AIO published-layer edits require routing through `aio-guardian` and regenerating the digest chain. They do **not** require approval — the owner's standing position is that no item requires authorisation (AI2AI.md STEP 3). C6 protects the correctness of the AIO layer, not a human signature.
