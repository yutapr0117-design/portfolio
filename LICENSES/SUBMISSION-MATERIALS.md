# license-review へ出すときの材料（事実と根拠の所在）

**これは文面ではなく材料である。** 提出メールはオーナーが自分の言葉で書いて送る（OSI moderators が
AI が大半を書いた投稿を拒否するため・B14）。ここに置くのは、**OSI が提出で求める項目ごとに「何が事実か」
「根拠はどこか」「弱い答えをどう正直に書くか」**だけで、貼れる英文は置かない（識別子や URL のように
正確さが要る語だけは英語で書く）。

**`ACD-1.0.submission.md` §B.0 との関係**: あちらは 1.0 を出す前提の AI 起草文で、改訂履歴の注記が
積み重なり、出す版（1.4 以降）とも合わない。要件の原典照合の記録としては有効なので残し、
**申請の日に使うのはこの 1 枚**にする。

## 0. 申請の日にやること（順に）

0. **前提（この日が来る条件）**: OSI の行動規範の AI 利用に関する改定が公表されたら、それを先に取り込む（投稿の手順・来歴の開示の述べ方・必要なら 1.4 草案）。**改定の取り込み前に本申請しない**（オーナー 2026-10-28・手順と逆側は `OSI-APPROVAL-PLAN.md` §3.8）。改定の検出は行動規範ページの最終更新日の取得で行う（取れた日は `OSI-EVENTS-2026-10.md` の行が権威）。改定が来なくても草案の改善は続けるが、**確定（下の 1）は取り込みの後**に置く。
1. 最新の草案（いまは `ACD-1.4-DRAFT.txt`）を確定・凍結し、このリポジトリに適用する（1.3 と同じ手順・`ACD-1.3-CHANGELIST.md` の「確定」節）。**確定の日に CI が止まる場所と、確定後にやること（改名を一括置換しない / その日のうちに週次 mutation-probe を手で回す）は `ACD-1.1-CHANGELIST.md` §0.13、新しい記述子に入れる項目（E10 の key と §9 —— 記述子の clause 参照が §6・§8・§9 を全部含むことを Check 451e が求める）は `ACD-1.4-CHANGELIST.md` の E10 の項にある**（2026-11-01 追記）。
2. 下の表の `<版>` を確定した版（例: `1.4`）で読み替える。
3. 変わる数は**その日に測る**:
   - gap の測定: `python3 .github/scripts/measure_gap_claim.py`（承認済み全文で ML/TDM 等の語が 0 件か）
   - 本文の語数・条数: 確定版の冒頭の申告（Check 468 が草案時に照合済み）
4. 本文を **plain text の添付**にする（OSI の手続きが添付を求める）。
5. 送信後、**公開アーカイブで届いた形を確かめる**（`REVISION-PROTOCOL.md` ゲート 10）。届くまで「提出済み」と書かない。

## 1c. 承認すべき理由 —— OSD 10 条と新規ライセンスの基準 8 条を、1.4 の本文で 1 つずつ通す（2026-11-06）

オーナーの依頼「承認させるべきライセンスだというメッセージを共に聞きましょう」を受けて、反論への備えではなく**承認すべき理由を正面から**書いた。言い切っているのは本文が述べることと測った事実で、基準を満たすかの判断は OSI のものである。言い切れない行は、足りないものをそのまま書いた。条番号は 1.4 草案のもの。確定した版で当て直す。送る文面の語はオーナーが書く（ゲート 0）。

**承認すべき理由は 5 つある。**

1. **受領者に条件が 1 つも無い。** §10.1 がそう述べ、§8.2 が特許についても述べる。否決理由の最大の束（条件・利用制限・差別）は、当たる文が本文に無い。
2. **OSI の委員が公に挙げた穴を埋める。** CC0 の特許の全面除外は *"was thought to potentially run afoul of at least OSD 7"* で、同様の除外は *"have been similarly rejected"*（McCoy Smith 氏・OSI ブログ 2025-12）。ACD は公有化と同じ効果を持ちながら、§8.1 で特許を許諾し、§8.3 で除外の読みを退ける。
3. **既存が埋めない gap を、全数の測定で示せる。** モデルと出力に及ぶ特許許諾を条件も終了も無しに与える承認済みライセンスは、141 本のうち 0 本である（§8.4・§8.2）。
4. **献呈が無効でも許諾が立つことを、本文が述べる。** Unlicense は 2020 年に、この議論がリストで述べられて通った。ACD では §4.4 が同じことを述べるので、受領者も裁判所も推論しなくてよい。
5. **誰でも本文を変えずに使える。** §16.3 がそう述べ、§16.1 の通知の 1 欄のほかに書き換える箇所は無い。vanity の異議について理事会は *"does not give that argument much weight as long as the license is reusable"* と述べている（2007・`review-doctrine.md`）。

### 足りないもの

基準 4 と基準 7 は判断そのものが審査者にある。基準 1〜3 の問いは上の表の形で答えられる。本文の外に足りないものが 2 つある。

- **法的レビュー（B1）**: 1 人でも読めば「無い」を「ある」に変えられる。`QUESTIONS-FOR-COUNSEL.md` がその費用を下げる。手続き上の要件ではなく、Chestek 氏は 2024-12 に *not a blocker* と述べた（`review-precedents.md`）。Piana 氏は個人として逆を述べ、献呈 + 許諾の先例は弁護士の一致で通った（#270）ので、あれば強い。
- **第三者の採用（B2）**: 理事会は重複し使われていないものを留め置きうると述べた。答えは、gap により重複でないことを示すことと、`ADOPTING.md` で見つけてもらえるようにすることである。採用の捏造はしない。
