# 盲点の探し方 —— どの次元をまだ測っていないか

**54 件の不利な事実のうち、後半に出たものほど「次元そのものが未検査」だった。**
個々の発見より、**どうやって見つかったか**のほうが再利用できる。この文書は
「次に何を探すか」ではなく「**次にどの測り方を使うか**」を残す。

## 中心にある観察

> **盲点は「まだ探していない場所」ではなく「まだ使っていない測り方」に在る。**

同じ次元で掘り続けると収穫は逓減する。実際、条文の敵対的読解は 4 巡目から
「既に答えてある」が増えた。一方、**次元を変えると 1 回目から出る** ——
言語の次元（#53）とリンク構造の次元（#54）は、どちらも**最初の測定で欠陥を出した**。

理由は単純で、**その次元を測る検査が 1 つも無かった**からである。内容を読む検査を
何百回走らせても、ファイルが何語で書かれているかは分からない。

## 使い終わった次元（もう収穫が薄い）

| 次元 | 何を測ったか | 出たもの |
|---|---|---|
| 条文の敵対的読解 | 各条を「攻撃する側」から読む | #15〜#23 ほか多数。4 巡目以降は逓減 |
| 引用の解決性 | ドシエの `§N.M` が本文に実在するか | 全解決（clean） |
| 記述の正確性 | 各条の説明が本文と一致するか | #34 #35 #36 |
| 自己言及的主張 | 「〜は無い」が本当に無いか | 9 件すべて真（clean） |
| 内部整合 | 番号の連番・相互参照・errata との対応 | E7 の欠落 |
| 自己申告の件数 | 「N 件」が実測と合うか | #52 ほか 5 件 stale |
| 時間軸 | 外部の事実に観測日があるか | #51（21 件すべて日付なし） |
| 語彙の計量 | 特定語の出現回数 | #50（software 0 回） |
| **言語** | **各ファイルが何語で書かれているか** | **#53（入口が誤案内）** |
| **リンク構造** | **文書間の被リンク数** | **#54（索引が最も孤立）** |
| **時系列** | frontmatter の日付 vs git の最終更新日 | **#55（12 件が最大 10 日 stale）** |
| **重複** | 複数文書に現れる同一文 | 6 件すべて意図的な引用で内容も一致（clean） |

## まだ使っていない測り方（候補・優先順位なし）

**思いついた順に書く。優先順位を付けると、付けた根拠のほうが先に古くなる。**

- **長さの分布** —— 極端に短い節・極端に長い節。長さは労力ではなく**不安の指標**でもある
- **読む順序** —— ディレクトリを上から順に開いた人が、何を最初に読むか（#45 は読み順で起きた）
- **想定読者の網羅** —— frontmatter が挙げる audience のうち、実際に宛てて書かれていない層
- **否定形の分布** —— 「〜ではない」が多い文書は、**何かを守っている**可能性
- **外部リンクの生死** —— アーカイブ URL が将来も解決するか
- **図表の有無** —— 表で示すべきものを散文で書いている箇所（逆も）
- **機械可読層との一致** —— `machine.json` の各主張が散文の主張と食い違わないか
- **ファイルサイズの偏り** —— 1 つの文書が肥大していないか（本体は Check 52/365 が見るが LICENSES/ は対象外）

## この文書自身の限界

**候補リストは、私が思いつける次元しか含まない。** 「まだ使っていない測り方」を
網羅的に列挙することは原理的にできない —— **列挙できるならそれは既に使った次元である**。

だから**この一覧が尽きても、盲点が尽きたことにはならない**。#52 で記録したとおり、
「発見がゼロ」は「その日のレンズでは出なかった」以上を意味しない。

**外から新しい次元を示唆されたときは、それが最も価値が高い** —— 自分の中から出ない
からこそ盲点なのであって、#53 と #54 はどちらも外からの示唆で始まった。示唆は
**具体的な欠陥ではなく次元の名前**で受け取るのがよい。欠陥を教えられると、それを直して
終わってしまう。
