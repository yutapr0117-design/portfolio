# OSI Approval Bottleneck Register

**この文書が唯一の canonical なボトルネック一覧である。** 他の文書はここを参照し、
同じ問題を独立に管理しない。

**目的は欠陥を数えることではない。** 目的は **OSI Approved への到達を阻害する要因を除去し、
残る不可制御要因を減らすこと**である。不利な事実（`against.md`）は**入力**であって、
ここに載るのは**承認確率に効くもの**だけである。

## 解消可能性の分類

`1` 文言修正 / `2` 条項削除 / `3` 条項縮小 / `4` 条項統合 / `5` 構造変更 /
`6` 名称・識別子変更 / `7` 提出方法変更 / `8` 法律家レビュー / `9` 外部証拠・第三者利用 /
`10` OSI 判断依存 / `11` 解消方法不明 / `12` 構造的に両立不能の可能性

**`11` と `12` を最優先で探索する。** 軽微な修正可能事項を大量に見つけても安心しない。
**1 件の構造的問題は 100 件の軽微 errata より重い。**

## B5 —— §4.4 第 2 文。**唯一、外からの答えを待っている項目である**

**なぜ承認上の問題か（事実）**: §4.4 第 2 文は
*"Where Section 3 is effective, this Section is redundant but not void, and it remains available to
be relied upon by You."* と述べる。**献呈が成功した場合を正しく描写しているかについて、
読みが 2 つ立つ。**

| 読み | 内容 |
|---|---|
| **A** | §4.1 は現在の無条件の許諾であり、その存在は §3 の失敗に依存しない。ゆえに §3 が成功すれば単に冗長になるだけで、先に与えた独立の許諾は無効にならない |
| **B** | 許諾は独立だが、**Covered Right が実際に手放された後は、許諾が作用する排他権がもう存在しない**。その権利について「依拠し続けられる」と述べるのは不正確でありうる |

**受領者から見た結果はどちらでも同じである** ——権利が消えていれば許可は不要、残っていれば §4.1 が与える。
**したがってこれは「誰かが自由かどうか」ではなく「§4.4 が法的経路を正しく述べているか」の問題である。**

**分岐**: (1) **設計の問題** ——献呈と無条件の現在許諾を、そもそも独立並行の footing として
構成すべきでない / (2) **起草の問題** ——構成は妥当で、§4.4 が「消えた権利の上で作用し続ける」と
言い過ぎているだけ。この場合の修正は**独立性だけを述べてそこで止めること**。

**なぜ AI が決めないか**: **これはドシエで唯一、内部で見つけたのではなく steward が
`license-discuss` に自ら出した問い**である（2026-09-06 の 2 通目・`errata.md` **E11**）。
**答えは外から来る。** そして **steward は「現在の文言が既に coherent なら、不要な改訂はしたくない」
と明言している** ——**凍結中の本文を、答えが来る前に触らない理由がここにもある。**

**status: 外部回答待ち。** **B14 により、その問いへの回答が来る経路も現在は止まっている**
（`license-discuss` は返信ゼロで、発信も止めている）。**B5 は B1 と同じく「提出の産物」側の項目である。**

**外部確認**: **必要（定義上）。**

## B6 —— 名称。**識別子は空いている。問題は「Commons」と「Dedication」の 2 語である**

**#112 が記録したとおり、我々は数週間テキストを敵対的に読みながら、
「名前そのもの」を一度も検査していなかった。** 0BSD の改名は `license-review` で 54 通を要している。

**⚠ この測定は新しくない。** `AS-OF.md` に **2026-09-09 付**で同じ測定が既に在り、
**しかもそちらの方が詳しい**（最近似は `CAL-1.0` "Cryptographic Autonomy License" で語幹のみ共有、
という事実をこちらは持っていなかった）。**本節が足したのは disposition であって測定ではない。**
**「初めて検査した」と書きかけて、grep して取り下げた** —— #88 / #92 と同じ形
（**「X はどこにも無い」と書く前に X を grep する**）。

**測定（SPDX License List 3.28.0・727 件・`AS-OF.md` 2026-09-09 / 本増分で 2026-09-10 に再確認）**

| 検査 | 結果 |
|---|---|
| `ACD` で始まる識別子 | **0 件。空いている** |
| 名称に "Autonomous" を含むもの | **0 件** |
| 名称に **"Commons"** を含むもの | **58 件 —— 内訳は Creative Commons 55 / Open Data Commons 3。例外なし** |
| 名称に "Dedication" を含むもの | 2 件（`CC-PDDC` / **`PDDL-1.0` = *"Public Domain **Dedication & License**"***）—— **ただしどちらも OSI 承認ではない**。**命名の先例ではあるが、承認の先例ではない** |

**そこから出る 2 点**

1. **"Commons" は、この名前空間では事実上 2 つの組織のハウスマークである**（58 件すべて）。
   **商標の主張は誰もしていないし、我々も §11 で商標を持ち出さない。**
   だが**審査者が「Commons 系列の一員」と読む余地**はあり、
   **名前は merits として争われる**（#112）。
2. **"Dedication" だけの名前は、この instrument の半分しか言っていない。**
   本体は**献呈（§3）と、それとは独立に付与される許諾（§4・§4.4）**である。
   **委員長の *"Which is it, a dedication to the public domain or a license?"*（#110）は、
   名前そのものによって強められている。**
   **そして同じ表に、その解き方が載っている** —— PDDL は
   ***"Public Domain Dedication & License"*** と名乗る。
   **ただし PDDL は OSI 承認ではない。使えるのは「名前でその対を表す前例が在る」ことまでで、
   「その対が承認された」ことではない。**

**最小の解消方法**: **1.0 は改名しない。** 凍結中であり、この名前で既に投稿され、
識別子は `machine.json` / `spdx.xml` / `FROZEN.md` / Check 441・453 に pin されている。
**successor 候補として、両方の半分を名前に持たせる案を記録する。**

**変更によって失うもの**: 改名は**継続性を失う** —— 既に公開した名前・識別子・digest・
`rounds/` の投稿本文がすべて旧名を指す。**#108（REUSE の命名要件）とも二重に絡む。**

**副作用・新たな反論**: 名前を変えれば「中身が変わった」と読まれる。
**逆に変えなければ、"Which is it" に対して名前が反証材料であり続ける。**
**どちらも実在する費用であり、片方だけを書かない。**

**外部確認**: 不要（測定は完了）。**status: 1.0 は改名しない。識別子の穴（E14）は 1.1 草案で閉じた** ——`ACD-N` / `ACD-N.N` の族へ保護を広げてある。**名前そのもの（"Commons" / "Dedication"）は草案でも変えていない** ——**改名が継続性を失うという費用は、識別子の穴を塞いでも消えない**からである。

**2026-09-10 追記（敵対的な利用者の視点で読んで出た）**: **§16.4 の保護は名前と識別子で非対称である。**
名前 *"Autonomous Commons Dedication"* は版を含まない形で書かれているので後続版にも及ぶが、
**識別子は `ACD-1.0` だけ**なので、**第三者が改変版を `ACD-1.1` として頒布しても条文には当たらない。**
**我々自身が 1.1 を予定しているため実務的な空きである**（`errata.md` **E14**）。
**承認されれば SPDX が識別子を固定するので、この穴は B11 と同じく承認で縮む。**

## B7 —— §8.4 の特許射程。**B10 と一方向に結ばれており、独立には動かせない**

**なぜ承認上の問題か（事実）**: McCoy Smith 氏が別の提出について
*"it is an issue as to whether a license of this scope would gain significant uptake
at least from patent holders"* と述べている（`license-review` 2025-05-14・#107）。
**ACD-1.0 の §8.4 は、Computational Use と、そこから生じる model / parameter set / weight /
embedding / output にまで特許許諾を及ぼす。** 射程はこの発言が想定するものより広い。

**そして uptake は我々が既に落ちている基準である**（B2・採用 1 件）。
**gap を担う条項が、採用を下げる条項でもある** ——これが B7 の実体である。

**条文から確定すること（読んで確かめた）**

1. **費用を負うのは特許を持つ採用者だけである。** §8.5 が *"reach only patent claims the
   Dedicator owns or controls"* と限っているので、**特許を持たない採用者は何も手放さない。**
   uptake への影響は**採用者全体ではなく、特許保有者という部分集合**に限られる。
2. **報復条項で緩和する道は、構造上ふさがっている。** §8.2 は報復条項の不在を
   *"deliberate"* と明言する。**報復条項は条件であり、§10.1（条件の不在）と §4.3 に正面から反する。**
   ACD-1.0 の中核主張は「何も課さない」ことなので、**uptake のために条件を足すのは、
   主張そのものを捨てることになる。**
3. **opt-out で緩和する道もふさがっている。** 留保・オプトアウトは §6.2 が
   *"makes no Reservation … and expressly declines to make one"* と否定した当のものである。
4. **したがって残る調整は「射程を狭める」しかない。** ところが §8.4 は
   **gap 3 件のうちの 1 件そのもの**である（`ACD-1.1-CHANGELIST.md` §2.6 の測定で 583 語の §8）。
   **狭めれば B10（新規性の根拠が残っているか・最高位）が縮む。**

**結論: B7 は独立の項目ではなく、B10 との一方向の取引である。**
**uptake を上げる方向の変更は、例外なく gap を削る。** B1 + B2 が 1 文で結ばれていたのと同じく、
**B7 と B10 も切り離して扱ってはならない。**

**変更によって失うもの / 残る gap**: 上記のとおり、**失うのは gap そのもの**であり、
**残るのは「特許保有者の採用が薄い」という不利な事実**（#107）である。**どちらも消せない。**

**副作用・新たな反論**: §8.4 を残す判断を明文化すると、
「**採用されないと知りながら残した**」と読まれうる。**それは正しい要約である** ——
我々は uptake より gap を選んでいる。**その選択自体を隠さずに書く。**

**外部確認**: 不要（判断は一次資料と条文から出る）。**status: 取引として記録済み・変更しない。**

**2026-09-10 追記（外部の一次資料）**: `license-review` は 2026-09 に**終了トリガーの境界**を
論じている（Fontana 氏「著作権に何か特別なものがあるのか、特許にあるのか」／Gay 氏「価格の存在と、
その価格が自由と整合するかは別の問い」）。**§8.2 はどの種類の主張でも終了しないので、この論争に
乗る面が無い**（`reviewer-positions.md` §1.69）。**ただし「係争域の外」は有利にも不利にも読める** ——
**争点を持たないことは、審査者が労力を割く理由も持たないことでありうる。**

**2026-09-10 追記（同じ敵対的読解から）**: **§8.4 の *"resulting from that use"* には程度の限定が無い。**
巨大なコーパスに本著作物を**極少量混ぜて学習したモデル**も「その使用から生じた」と主張しうる読みを
条文が誘う（`errata.md` **E15**・**裁判所がそこまで読むかは分からない。述べているのは条文が誘う読み**）。
**これは B7 の取引をさらに鋭くする** ——閾値を入れれば特許保有者の懸念（#107）に応えられるが、
**その閾値こそが gap の一部**であり、B10 を縮める。

## B8 —— §12 人格権。**同じ条項が「gap」と「mission creep」の両方で名指しされている**

**この項目が難しいのは、賛否が割れているからではなく、賛否が同じ条項の別の面を見ているからである。**

**不利な側（3 件・いずれも一次資料）**

| 発言 | どこに当たるか |
|---|---|
| Carlo Piana 氏 *"these are **not licensable**, so anything the license says one way or the other, nothing changes"*（`license-review` 2023-11・#104）| **§12.1（放棄）に当たる。** ただし §12.2（不行使の合意）は**約束**であって許諾ではないので、同じ反論では倒れない |
| Pamela Chestek 氏が人格権条項の追加を **"mission creep"** と名指し（`license-discuss` 2026-06-23・#6）| **§12 全体に当たる。** 「ライセンスは著作権を扱うもので、人格権まで手を伸ばすのは範囲外だ」という筋 |
| **法域による非対称**（#118・2026-09-09 に自分で発見）| **§12.5 に当たる。** 虚偽の帰属に対抗する利益は、放棄が有効な法域では放棄され、**放棄不能な法域でだけ残る** ——「一貫していない」と読まれうる |

**有利な側（1 件・そして重い）**

Shuji Sado 氏（Open Source Group Japan 会長）は 2024-03 に、**著作権だけを述べるライセンス**は
—— Blue Oak を例に、0BSD と MIT-0 も同じ読みだとして ——
***"not open source, at least not in Japan"*** と論じている（§1.59）。**理由は同一性保持権が
日本ではソフトウェアに及び、改変を止めるのに使えるからである。**

**つまり同じ §12 が、一方では「範囲外」と呼ばれ、他方では「これが無いと OSD 3 を
満たさない法域がある」と論じられている。** どちらも `license-discuss` / `license-review` 上の発言である。

**分岐（決めるのは我々ではない）**

| もし審査者が採るなら | §12 に起きること | 我々に残るもの |
|---|---|---|
| 「人格権は licensable でない」（Piana 氏）| §12.1 は無害だが**空**になる | **§12.2 は残る**（不行使の約束）。ただし約束が人格権について有効かは別途争われる |
| 「mission creep」（Chestek 氏）| §12 を削れという圧力 | **Sado 氏の論点が答えになる** ——削れば、日本で改変が止まりうる |
| 「法域で結果が変わるのは不整合」（#118）| §12.5 の書き直し | **1.1 候補として記録済み**（`errata.md` / §12 の非対称を条文の側から説明する）|

**最小の解消方法（分類 1・提示の変更）**: **§12 を「人格権も扱う」ではなく
「改変の自由を、著作権だけでは保証できない法域で保証するための条項」として提示する。**
**mission creep への答えは、範囲の弁明ではなく OSD 3 との接続である。**

**変更によって失うもの**: 無し（提示の変更のみ）。**条文は凍結中で触らない。**

**残る gap**: **§12 が有効かどうかは、我々には決められない。**
§12.2 は「不行使の約束」であって、**それが人格権について各法域で有効かは弁護士の領域**である
（B1 と同じ壁）。**「無効かもしれない」と書いてある条項を、有効であるかのように書かない。**

**外部確認**: **必要**（B1 と同じ）。**status: 分岐を記録済み・提示のみ調整可。**

## B9 —— §7 データベース権。「未検証・削除候補」だったので、検証した。**削除しない**

**検証したこと**: §7 は 67 語 2 項。**§1.5（Covered Rights の定義）が既に
*"sui generis database rights"* と *"rights against unfair extraction"* を含んでいる**ので、
**§7 は丸ごと重複ではないか**を確かめた。

### B1（法的レビュー）——「待ち」に分類してはならない

**register の表は B1 を「法律家確認待ち」と書いている。この語は誤解を招くので、ここで打ち消す。**
§1.52 が一次資料から確定しているとおり、**このリストの審査者は pro bono の弁護士**であり
（Piana 氏 *"who mostly do this job pro bono, as we are doing now"*・Berkus 氏 *"our volunteer
attorneys"*）、**提出することが、単独起草者が弁護士の目を通す経路そのものである。**

**帰結: B1 は「提出前に満たすべき前提条件」ではなく「提出の産物」である。**
弁護士を待って提出を遅らせるのは、**得られるはずのものを得ない**だけになる。
**AI がこれを解くことはできない。解く手続きは提出である。**

**副作用（自分で作りうる新たな反論）**: §4c を「法的レビューの代替」として提示すると、
McCoy 氏の上記発言に正面から当たる。**§4c は既にその危険を自分で塞いでいる** ——
*"None of these substitute for legal review. They only mean that the failures a machine can find
are not present."* **この 1 文を落としてはならない。**

### B2（実使用 1 件）——**作れない。制御できるのは discoverability だけ**

**採用は捏造できない。** 存在しない採用を書けば、それは提出の失格事由であって弱点ではない
（`REVISION-PROTOCOL.md` の規律・オーナー確認済み事実の扱いと同じ）。
**時間と第三者の選択だけが動かす。**

**AI が制御できるのは「見つけられること」だけ**で、実施済みの梃子は 2 つ ——**(1) 2026-09-10 に英語の招待を README の先頭ブロックへ足した**（それまで「あなたの著作物にも使える」は**日本語にしかなく**、採用は日本語圏の外から来る必要がある。**招待と警告を同じブロックに置く** ——法的レビュー無し / OSI 未承認 / SPDX 未登録）、**(2)** 元の梃子は
**README に「誰でも自分の著作物に使える」を招待と警告を同じ文で置いたこと**（#85 の 1 面外側）。
**それ以上は、待つことと、テキストを正しくすること（＝ B3 / B10）に還元される。**

**なぜ B2 に「解消可能・未実施」と書いてあるか**: 採用は原理的に到達可能だからで、
**我々の作業で到達可能という意味ではない。** この区別を落とすと、次のセッションが
「まだやっていない作業」を探して見つからず、時間を使う。

### この節が establish しないこと

- **どちらの枝も、この節では 1 ミリも解消していない。** 記録したのは**分類の誤り**
  （B1 を待ちに置いていたこと）と、**2 つが 1 文で結ばれているという事実**である。
- **逆向きの記録（"not a blocker"）を根拠に「大丈夫だ」と読んではならない。**
  同じアーカイブに、両枝欠如を理由に Board へ非承認を求めた実例がある。
  **有利な材料と不利な材料は、同じ場所に同じ重さで置く。**

## B4 —— §3 献呈と §4 許諾の並存。class 12 候補として検証し、否定した

**なぜ承認上の問題か（事実）**: Licensing Committee 委員長が
*"Which is it, a dedication to the public domain or a license? **You can't have it both ways.**
… The document is internally contradictory."*（2025-10-16）と述べている。
ACD-1.0 の中核はまさにその並置である（§2.4 / §4.4）。

**class 12 でない理由（一次情報・2026-09-09）**

1. **彼女の批判の対象は並置ではない。** 挙げられた「留保」は 4 つ ——虚偽の著作者主張 /
   違法利用条項 / 特許訴訟による終了 / 責任否認 —— で、**ACD-1.0 に在るのは 1 つだけ**
   （§11.3 / §12.5・`objection-map.md`）。**批判の実体は「全部放棄と言いながら個別に留保する」
   ことであって、献呈と許諾を同居させることではない。**
2. **Unlicense は献呈＋列挙された許諾で承認されている**（2020）。委員会の記録は
   「**献呈単独では**承認しない」であり、ACD-1.0 は単独ではない。
   **そしてその救済論拠（献呈が無効でも列挙された許諾が働く）は Unlicense の条文に無く、
   §4.4 はそれを条文にしている。**
3. `PDDL-1.0` は *"Public Domain **Dedication & License**"* と名乗る既存 instrument である
   （**OSI 承認ではない**が、命名として前例が無いわけではない）。

**結論: class 10（OSI 判断依存）。** 技術的に直すだけでは決まらないが、
**構造的両立不能ではない。**

**🔴 残る作業についての記述を訂正した（2026-09-09・#118）。** ここは当初「§11.3 / §12.5 が**留保ではなく reach の限界**であることを示す」と書いていた。**§12.5 についてこれは誤りである** —— §12.5 は実際に利益を残す条項で、`clause-reference.md` は最初からそう書いていた。**2 条のうち 1 条だけを読んで 2 条について結論した。**

## B10 —— gap が本当に残っているか（最重要・OSI 判断依存）

**2026-09-10 の測定（第 1 の枝は確かめられる）**: **承認済み 149 件の本文をすべて取得して数えた**
（SPDX 3.28.0・取得失敗 0）——`machine learning` **0 件** / `text and data mining` **0 件** /
`machine-generated` **0 件** / `train` 系 **1 件**（`Frameworx-1.0`・無関係な用法）/
`model` **16 件**（実見したものは *"product model"* / *"Blue Oak **Model** License"* /
*"open source **model**"* で、**機械学習のモデルではない**）。

**これが establish すること**: **どの承認済みライセンスも、これらの主題を明示的には扱っていない。**
**establish しないこと**: **機械学習が許諾されていないこと** ——permissive ライセンスは
「すべての利用」を許すことで暗黙に許している。**我々が擁護できる主張は「明示の有無」と
「沈黙が未解決に残すもの」（留保機構・モデルと出力に及ぶ特許・そもそも著作権が生じるか）であり、
それは §6.5 が述べていることそのものである。**

**第 2・第 3 の枝も同日に測った**: **92 / 149 が特許に言及する**が、`output` を含む 30 件のうち
**主要 10 件では `output` が `patent` の 250 字以内に一度も現れない**（GPL 系の *"output from
running the Program"* は**著作権の話であって特許ではない**）。**`subsist` は 149 件中 0 件** ——
**権利が「生じているか」という語彙を使う承認済みライセンスは 1 つも無い。**
**establish しないこと**: 解釈上 output に及ばないこと。**測れるのは語の不在であって、効果は裁判所が決める。**

**残る枝は依然として OSI の判断である** ——**gap が在ることと、その gap が新しいライセンスを
承認するに足ることは別**であり、後者は測れない。

**gap を担う条項は 3 つに絞られる**（B3 の測定より）——
**§6**（ML / TDM の明示的許諾と Reservation の否認）/ **§8.4**（特許がモデル・出力に及ぶ）/
**§9**（機械生成物に権利が存するか否かと無関係に許諾が成立する）。

**この 3 つを削ると、ACD-1.0 は 0BSD / Unlicense に収束する**（§27 の失敗）。
**逆にこの 3 つ以外はすべて削減候補である。**

**判断が OSI 側にある部分**: 「この 3 つは既存の承認済みライセンスで代替できないか」。
**現時点で我々が示せるのは、6 本（MIT / MIT-0 / 0BSD / Apache-2.0 / CC0 / Unlicense）の
どれもこの 3 つを同時には持たない、という事実まで**である。
