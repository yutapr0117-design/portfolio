# ACD-1.0 — 逐条リファレンス（全 16 節 82 条）

```
本書の役割 : 「この条項は何のためにあるのか」に**全条項について**答える
本書の性質 : 非規範。ライセンス本文の一部ではない。**齟齬があれば本文が勝つ**
完全性     : 82 条すべてを収録。本文から条項を機械抽出して照合しており、
             条項の追加・削除があれば生成時に検出される（欠落があると書けない）
```

## 0. 使い方

想定問答（`ACD-1.0.review-responses*.md`）は「**来るであろう指摘**」に答える。本書は
「**この条項は何か**」に答える。読み手が条番号を持っているとき（レビューでの引用、
採用検討時の疑問、監査での照合）は、まずここを引く。

各行は次の 2 列で書いてある。**条文の言い換えは書かない**（それは本文を読めばよい）。

| 列 | 内容 |
|---|---|
| **定めること** | その条項が何を規律するか。要点のみ |
| **なぜ必要か / 無いとどうなるか** | **本書の価値はここにある。** 削ったら何が壊れるか、どの反論に備えているか |

**ここに書いていない疑問が出たら、それは本書の欠落である。** 追記して、次の読み手が同じ
ところで止まらないようにすること。

## §1. DEFINITIONS

定義。**何を定義しないか**も設計であり、特許・商標・人格権を Covered Rights から外していることが §8・§11・§12 の存在理由になる。

| 条 | 定めること | なぜ必要か / 無いとどうなるか |
|---|---|---|
| **1.1** | この文書自体（§1〜§16）を「Dedication」と定義する | 以降のすべての条文が自分を指せるようになる。範囲を明示しないと、付属文書や README の記述まで条文の一部と読まれうる |
| **1.2** | 「Work」= 適用対象。source / object / documentation / **data / metadata / audiovisual** と collection を含む | **ソフトウェアに限定しない**のが要点。0BSD 等は「software」を前提にするため、データセットや音声・画像に適用したとき射程が争える |
| **1.3** | 「Dedicator」= 適用した者。複数いる場合は**各自について個別に**作用し、一人の失敗が他に波及しない | 共同著作物で 1 人の献呈が無効でも全体が崩れない。これが無いと、後から誰か 1 人の権利に瑕疵が見つかった時点で全員分が疑われる |
| **1.4** | 「You」= 権限を行使する者。**人・組織・自動化システム**を含み、自動システムの場合は運用者と委託者の双方に等しく及ぶ | **「法人格が無いから権限が成立しない」という抜け穴を塞ぐ**。学習パイプラインやエージェントが実行主体になる場面を想定している |
| **1.5** | 「Covered Rights」= 著作権・実演・放送・録音・sui generis DB 権など。**特許・商標・人格権は除外**し §8/§11/§12 が扱う | 除外を明示するので、§8.4 のような特許側の手当てが「念のため」ではなく**必要な独立の許諾**になる（§8.4 自身がそう述べる） |
| **1.6** | 「Moral Rights」= 氏名表示・同一性保持など | §12 が扱う対象を確定する。多くの法域で譲渡・放棄が制限されるため、Covered Rights と分けないと §3 全体の有効性が疑われる |
| **1.7** | 「Computational Use」= 自動処理全般（学習・TDM を含む） | §6 と §8.4 が同じ語で射程を共有する。語を分けると、著作権側は許すが特許側は別語で狭い、というずれが生じる |
| **1.8** | 「Machine-Generated Material」= 機械が生成した部分 | §9 が扱う対象。**この repo 自身がその典型**であり、定義を置かないと §9 が何に適用されるのか読み手が判断できない |
| **1.9** | 「Contribution」= 提出される改変等 | §2.6 が CLA 無しで取り込む仕組みを支える |
| **1.10** | 「Reservation」= TDM への opt-out（**EU DSM 指令 4 条 3 項**を含む） | **本文が引用する唯一の外部法令**。§6.2 が「留保しない」と述べるとき、何を留保しないのかが特定される |

## §2. SCOPE AND EFFECT

適用範囲と効力の発生。撤回不能性・受諾不要・**独立した多層構成**・承継人拘束・非 executory という、この instrument の骨格が全部ここにある。

| 条 | 定めること | なぜ必要か / 無いとどうなるか |
|---|---|---|
| **2.1** | Work 全体と**分離可能な各部分**に及ぶ | 一部だけ切り出して使う者が「全体に対する献呈だから部分には及ばない」と争われないようにする |
| **2.2** | 撤回不能。公開済みの複製に**後から条件を追加できない** | 「後出しで条件を付ける」経路を塞ぐ。§5.2(b) が契約や利用規約による同じ迂回を塞ぐ |
| **2.3** | **受諾行為なしに効力が生じる**。署名・登録・通知・同意は不要で、利用者の作為不作為で権限を失わない | OSD 7 に直接対応する。また **§15.7 が準拠法を定めない理由**でもある（合意していない相手に準拠法を課すのは筋が通らない） |
| **2.4** | §3・§4・§5・§6 は**互いに独立**。どれも他の失敗を条件にしない | **dedication 形式への最大の反論への回答**。公有化を認めない法域でも §4 のライセンスが独立に立つ |
| **2.5** | 利用者の**信頼（reliance）は目的であって副次的結果ではない**と述べ、約因・方式の欠如を理由に無効を主張しない（禁反言） | 無償の一方的許与が「約因が無い」と攻撃される典型に対する備え。**意図の表明が estoppel の基礎になる** |
| **2.6** | Contribution は自動的に本 Dedication の下で提出され、提出者が Dedicator になる。**CLA を要求できない** | 貢献のたびに別文書を要求する運用を封じる。取り込みを強制するものではない（受け入れ義務も無い） |
| **2.7** | **Dedicator が持つ権利にしか及ばない**。第三者の権利は影響を受けず、無瑕疵の表明でもない | 本 Dedication の**射程の限界**を示す中心条項。§8.5・§11.4・§13.2 が各面で同じ限界を繰り返す |
| **2.8** | §3・§4・§6・§8 は**承継人・譲受人・相続人・管財人**を法が許す限り拘束する | **権利が意に反して他人へ渡る経路**（相続・倒産・売却）を塞ぐ。拘束できると断言してはおらず、通知と禁反言の基礎を作る |
| **2.9** | 適用時点で**履行完了**し継続債務が無い＝ **未履行双務契約ではない**。倒産手続や管財人の行為に影響されない | 米国倒産法 §365(n) のような保護規定に頼らずに済む設計。管財人は §2.8 の「譲受人」にあたるとも明示する |

## §3. DEDICATION OF COVERED RIGHTS

放棄（public domain 化）。**認めない法域が多い**ので、単独では足りないことを前提に書かれている。

| 条 | 定めること | なぜ必要か / 無いとどうなるか |
|---|---|---|
| **3.1** | Covered Rights を**放棄・遺棄**し、それを認める法域では public domain に置く | 最も強い形の手当て。ただし多くの大陸法系では機能しないため §4 が独立に必要になる |
| **3.2** | 放棄は**存続期間全体**に及び、延長・回復・復活、および**報酬請求権・課金・使用料**も含む | 期間延長や私的録音録画補償金のような**後から生える請求権**を残さない |
| **3.3** | 放棄が認められないが**放棄（waiver）は認める**法域では waiver として扱う | 「放棄」概念の有無という法域差を、条文の側で吸収する |

## §4. LICENCE OF COVERED RIGHTS

ライセンス。§3 が効かない場合の受け皿だが、**§3 の失敗を条件にしない独立の許諾**である点が要。

| 条 | 定めること | なぜ必要か / 無いとどうなるか |
|---|---|---|
| **4.1** | 全世界・無償・非排他・**撤回不能**・永続・再許諾可・譲渡可のライセンス | §3 が効かない法域での**実効的な受け皿**。OSD 1 の根拠でもある |
| **4.2** | 複製・翻案・翻訳・改変・派生・公衆送信・頒布・貸与・販売・再許諾を**媒体と手段を問わず**含む | 列挙は限定ではない（§15.2 が「including は例示」と定める）。将来の手段まで及ぶと明記する |
| **4.3** | **いかなる条件も付さない**。帰属表示・通知の複製・相互ライセンス・ソース開示・利用分野・利用者の属性のいずれも条件にしない | OSD 5・6 の根拠。**§10.1 の中核**でもある |
| **4.4** | §3 とは**独立に**与えられ、§3 の無効を条件としない。§3 が有効なら冗長だが無効ではない。**利用者は §3 の有効性を判断しなくてよい** | 「まず §3 を試し、駄目なら §4」という**段階構成にしない**ことで、利用者が法域ごとの有効性を調べる負担を負わない |
| **4.5** | 条件が無いので、**任意の条件（本 Dedication と両立しない条件も含む）を付けて再頒布できる** | GPL 系プロジェクトへの取り込みが可能である根拠。OSD 1・9 に対応 |
| **4.6** | 追加条件は**自分が与えるもの**を規律するだけで、受領者と本 Dedication の関係を切らない | 再頒布者が「自分の条件だけが適用される」と主張して下流を締め出す経路を塞ぐ。§1.4・§5.3・§2.3 が根拠 |

## §5. COVENANT NOT TO ASSERT

不行使の約束。§3・§4 がいずれも争われても残る第三の足場で、**Dedicator を縛るもの**であって利用者への制限ではない。

| 条 | 定めること | なぜ必要か / 無いとどうなるか |
|---|---|---|
| **5.1** | Covered Right を**行使しない**、他人に行使させ・助けないという約束 | §3・§4 が争われても残る第三の足場。**契約・禁反言の一般法理で立つ** |
| **5.2** | (a) 技術的保護手段を適用せず回避規制を援用しない (b) **契約・利用規約・クリックスルー・登録要求など付随手段で義務を課さない** (c) §15.1 が要求するより狭い解釈を主張しない | **いずれも Dedicator を縛るもので、利用者への制限ではない**。(b) は「ライセンスでは自由、ダウンロードページで不自由」という迂回を塞ぐ |
| **5.3** | 約束は Work に**随伴**し、承継人を拘束し、**間接的に受け取った者も**受益者として援用できる | 再頒布の連鎖の先にいる人が、Dedicator と直接の関係が無くても援用できる |

## §6. MACHINE LEARNING, TEXT AND DATA MINING, AND MODEL TRAINING

機械学習・TDM。**許諾であって制限ではない** —— 近年この種のリストに来る AI 関連ライセンスの大半が制限であるため、最も誤読されやすい。

| 条 | 定めること | なぜ必要か / 無いとどうなるか |
|---|---|---|
| **6.1** | Computational Use を**目的を問わず明示的に許諾**する | OSD 6 との関係で最も誤読されやすい条項。**制限ではなく許諾である** |
| **6.2** | Dedicator は**いかなる Reservation もしない**と明言する | EU DSM 4 条 3 項の opt-out は「留保したか」で決まり、**沈黙が意味を持つ**領域。許諾の言明だけでは足りない |
| **6.3** | **他者**が行った Reservation については、それに触れない | §2.7 の一般原則の TDM 面。初期草案はここで**過大主張していたのを是正済み** |
| **6.4** | 学習で得られたモデル・パラメータ・重み・埋め込み・**出力**に本 Dedication は何も付着させない | 「学習を許すなら成果物にも権利が及ぶ」という推論を封じる。近年の一部のライセンス的文書が実際にそう主張するため、**沈黙が中立でなくなっている** |
| **6.5** | §6 は §3〜§5 が結果的に達することを**明示的に述べたもの**である | 冗長性の指摘を先回りして認める条項。そのうえで §6.2 の Reservation 面は冗長でないと示す |

## §7. SUI GENERIS DATABASE RIGHTS

sui generis データベース権。著作権とは別の権利なので、明示しないと「DB としての権利は残っている」と争える。

| 条 | 定めること | なぜ必要か / 無いとどうなるか |
|---|---|---|
| **7.1** | sui generis DB 権も Covered Right であり §3〜§6 が及ぶ | EU の DB 権は著作権と別物なので、含めないと「データベースとしての権利は残っている」と争える |
| **7.2** | 実質的部分の**反復的・体系的な抽出と再利用**を無制限・無条件に許す | DB 指令の用語（extraction / re-utilisation）で書くことで、**読み手が自分の法域の語彙で答えを見つけられる** |

## §8. PATENT LICENCE AND COVENANT

特許。**CC0 が明示的に除外した部分**であり、ACD-1.0 の存在理由の中心。学習済みモデルと出力にまで及ぶ点が新しい。

| 条 | 定めること | なぜ必要か / 無いとどうなるか |
|---|---|---|
| **8.1** | Dedicator が保有・支配する**全特許クレーム**について、製造・使用・販売・輸入等のライセンス | CC0 が明示的に**除外**した部分。ACD-1.0 と CC0 を分ける最大の差 |
| **8.2** | **条件なし・終了なし**。訴訟提起を理由とする終了規定を持たず、その**不在は意図的**である | Apache-2.0 §3 の防御的終了を敢えて持たない。条件を 1 つでも入れると §10.4「破れるものが無い」が崩れる |
| **8.3** | 特許を留保・温存する読み方を**拒絶**する。著作権だけ与えて特許を残すと受領者は露出したままになる | CC0 §4(a) 型の結果を明示的に否定する。§8.4 の存在理由そのもの |
| **8.4** | Computational Use と、そこから生じる**モデル・パラメータ・重み・埋め込み・出力**にも及ぶ特許ライセンス。**§8.1 の「Work に含まれる主題」という限定を意図的に外す** | §1.5 が特許を Covered Rights から除くため、§6.4 だけでは著作権面は許され特許面は露出する。**モデルは「Work に含まれる主題」ではない**ので、限定を持ち込むと救済が消える |
| **8.5** | §2.7 に従い、**Dedicator が持つクレームにしか及ばない**。非侵害の保証ではない | 特許ライセンスの射程を誤読させないための限界表示。§13.2 が対応する無保証を述べる |
| **8.6** | ライセンスが無効とされた法域では、同じ範囲の**不行使の約束**に切り替わる | §3 に対する §5 と同じ二段構え。ライセンス構成が否定されても実効を保つ |

## §9. MACHINE-GENERATED MATERIAL AND AUTHORSHIP

機械生成物。権利の存否という**未解決の問題を、利用者の経路から外す**ための節。

| 条 | 定めること | なぜ必要か / 無いとどうなるか |
|---|---|---|
| **9.1** | Work は全部または一部が機械生成でありうる | **このリポジトリ自身の事実**。隠さずに条文へ書いている |
| **9.2** | **権利が存在するとの表明をしない**。存在しなければ本 Dedication は何も足さず何も奪わない。存在すれば §3〜§8・§12 が全面適用される | 権利の有無という**未解決の問題を利用者の経路から外す**。どちらに転んでも利用者の立場が変わらない |
| **9.3** | **どの部分が機械生成かを判定する義務を負わない**。いかなる許諾もその判断に依存しない | 実務上ここが最重要。判定義務があると、利用のたびに調査コストが発生する |
| **9.4** | 由来の事実を否定するものではない。**虚偽の著作者表示は §11.3 が扱う** | 「権利が無い」ことと「誰が作ったか」は別問題だと切り分ける |

## §10. ABSENCE OF CONDITIONS

条件の不在。「何をしなくてよいか」を列挙し、慣習からの推測を封じる。

| 条 | 定めること | なぜ必要か / 無いとどうなるか |
|---|---|---|
| **10.1** | いかなる条件・義務・制限・要求も課さない | 本 Dedication の中核。§4.3 と対 |
| **10.2** | 帰属表示・通知の複製・改変の明示・ソース開示・再ライセンス・**本ファイルの保持**すら不要 | 「何をしなくてよいか」を列挙することで、慣習からの推測を封じる |
| **10.3** | **依頼・希望・慣習・期待は条件ではない**。帰属の依頼も同じで、従わなくても違反ではない | README の「引用してください」が条件と読まれる典型を封じる。**社会的な意味はあるが法的効果は無い**と明示 |
| **10.4** | **終了規定も復活規定も無い**。破れるものが無いから | §8.2 が防御的終了を持たない理由と同じ構造 |
| **10.5** | §16 は**文書としてのテキスト**を扱うもので、Work の利用条件ではない | §16.4 の verbatim 制限が「利用の条件」と誤読されるのを防ぐ |

## §11. TRADEMARKS, NAMES, AND MISREPRESENTATION

商標・氏名・虚偽表示。**許諾の限界**を示す節であり、条件ではない。

| 条 | 定めること | なぜ必要か / 無いとどうなるか |
|---|---|---|
| **11.1** | 商標・サービスマーク・商号・ロゴ・氏名の権利は**与えない** | Apache-2.0 §6 と同じ標準的な留保。§3〜§10 の許諾を減らすものではないと明示する |
| **11.2** | **名指しの言及（nominative use）は妨げない**。何であるか・どこから来たか・誰が作ったかを真実として述べてよい | §11.1 が「出所を語ってはいけない」と読まれるのを防ぐ |
| **11.3** | **虚偽の著作・是認・提携の表示は、そもそも Dedicator が許せる範囲外**。これは限界の表示であって条件ではない | OSD 6 に触れないことを条文自身が述べる。**商標法・不正競争法の領域**であり、ライセンスが許諾しうる対象ではない |
| **11.4** | Covered Rights・§8 の特許・§12 の人格権**以外には及ばない**。データ保護・プライバシー・パブリシティ・人格権は Dedicator のものではない | **学習されるための著作物はしばしば人に関するデータである**ため、どこで止まるかを読み手に明示する |

## §12. MORAL RIGHTS

人格権。法域差が最も大きく、放棄 → 不行使特約という**二段構え**を採る。

| 条 | 定めること | なぜ必要か / 無いとどうなるか |
|---|---|---|
| **12.1** | 各法域で許される最大限、人格権を**放棄し行使しない** | 放棄可能な法域ではこれで足りる |
| **12.2** | 放棄不能な法域では、代わりに**行使しない旨の約束**（不行使特約）に切り替わる | 日本法（著作権法 59 条）を含む法域への対処。**実務が実際に使う仕組み**に合わせている |

## §15. CONSTRUCTION AND SEVERABILITY

解釈と可分性。**法域差を吸収する装置**が集まっている。

| 条 | 定めること | なぜ必要か / 無いとどうなるか |
|---|---|---|
| **15.1** | **最も広い許諾・最も少ない義務**となるように解釈する。複数の読み方があるなら利用者に有利な読み方が優先 | 裁判所への指示ではなく**付与者の意図の表明**。実効は §5.2(c) の covenant 側にある |
| **15.2** | 単複の互換、「including」は例示、法令への言及は改正後を含む | 列挙が限定と読まれるのを防ぐ標準的な解釈規定 |
