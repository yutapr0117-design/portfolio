# 93 か月の掘削と、そこで検定した仮説（2026-09-17）

**`ACD-1.0.review-corpus.md` から切り出した**（985 行で advisory を鳴らしたため・
**節番号は動かしていない**ので既存の `§1.91` / `§1.93` 参照はここへ解決する）。

**corpus との境界**: corpus は**件数の census**（全期間を数えて参照クラスの大きさを出す）。
**ここは仮説の検定** ——「長さ / 新参 / 個人であること / 問いの重さ が、返信の有無を説明するか」。
**census は『どれだけ在るか』を、検定は『なぜそうなったか』を扱う。**

## 1.91 `license-discuss` を 2019-01〜2026-09（93 か月・2,420 通・299 スレッド）で掘り直した —— そして「長すぎたから返信が無い」は、我々の測り方の誤りだった（2026-09-17）

**掘った理由**: オーナーが 2026-09-17 に短い版を送るにあたり、「**8 月の投稿が長すぎた結果、議論が進まない**」
という読みを前提にしていた。**その前提を測ったら、崩れた。**

### 🔴 最大の発見 —— 8 月の投稿は、受信箱では 867 語だった

**アーカイブの当該ブロックを構造で読むと**、本文は署名まで **867 語**で終わり、そこから
`-------------- next part --------------` が **2 回**現れる ——1 回目は **HTML 版のスクラブ告知**、
2 回目が **添付された `ACD-1.0.txt` を pipermail が展開したもの**である。
**本文自身が *"The complete license text is attached as ACD-1.0.txt."* と述べており、実際に添付だった。**

**つまり 5,778 語（我々が「delivered」と呼んできた数）は、アーカイブの見え方であって受信箱の見え方ではない。**

**我々の道具が「delivered = 受け手の inbox に届いた本文全体」と定義していたのが誤り**で、
`measure_list_verbosity.py` は `next part` の後ろを本文として数えていた（訂正済み。
`inbox` / `attached` / `delivered` の 3 つに分けた）。

**この誤りは判断に効いていた** ——「8 月が長すぎた」は B3（長さ）の最も身近な証拠として使われていた。

**⚠ 逆側（同じ段落で書く）**: **アーカイブは公開記録であり、そこを読む人は 5,808 語に出会う。**
**添付という形式そのものを嫌う審査者もいる**（URL を好む）。そして **B3 の本体は無傷である** ——
委員長が engage しなかった 2 例（3,888 語 / 約 4,500 語）は**ライセンス本文の長さ**についてであって、
送り状の長さについてではない。**崩れたのは「8 月の*メール*が長すぎた」だけである。**

### 測定 1 —— 長さは、返信が付くかを予測しない

事務連絡・ダイジェストを除いた **299 スレッド**で、**最初のメッセージの語数**別に返信率を測った。

| 本文（散文）語数 | n | 返信あり | 割合 |
| :-- | --: | --: | --: |
| <200 | 157 | 109 | **69.4%** |
| 200–499 | 96 | 76 | **79.2%** |
| 500–999 | 36 | 26 | **72.2%** |
| ≥1000 | 10 | 7 | **70.0%** |

**アーカイブ上の展開量（引用・添付込み）で測っても同じ**（<300: 72.9% / 300–999: 72.3% /
1000–2999: 71.4% / ≥3000: **3 件すべて返信あり**）。**最長は 7,862 語（Project Tick・返信 8）。**

**したがって `license-discuss` では、長さは返信の有無をほとんど説明しない。**

### 測定 2 —— 初投稿者の方が、返信をもらっている

| 開始者 | n | 返信あり | 割合 |
| :-- | --: | --: | --: |
| **その人の初出スレッド** | 146 | 118 | **80.8%** |
| 常連 | 153 | 100 | 65.4% |

**「新参は無視される」は、この窓では成り立たない。**

### 測定 3 —— 沈黙がいつ情報になるか

返信が付いたスレッド（n=223）の**初回返信までの時間**: **中央値 8.1 時間**、
**24 時間以内 70.9% / 48 時間以内 85.7% / 1 週間以内 94.2%**（最大 3,437 時間）。
スレッド全体の **29.1% は最後まで返信ゼロ**。

**導かれる読み**: **1 週間沈黙したスレッドが、その後に返信を得る確率はおよそ 1 割**
（≈13 / 106）。**「まだ来ていない」と「来ない」の境目は、だいたい 1 週間である。**

### 測定 4 —— ライセンスを持ち込んだスレッド（n=28・8 年分）

**21 件（75.0%）に返信が付いた。返信ゼロは 7 件で、その内訳が重要である。**

| 日付 | 語数 | 件名（抜粋） |
| :-- | --: | :-- |
| 2019-01-18 | 66 | Proposed license decision process |
| 2020-01-04 | 40 | [License-review] AGPL timeline & why cautious processes |
| 2020-12-13 | 36 | [License-review] GDPR compliance through software licence |
| 2022-12-14 | 39 | [License-review] Final comment on Open Logistics Licen… |
| 2023-08-26 | 4 | [License-review] Request for Approval of 'new' Open Co… |
| **2026-08-26** | **867** | **Discussion Request: ACD-1.0** |
| **2026-09-06** | **835** | **Discussion Request: ACD-1.0 — one threshold question** |

**5 件は 4〜66 語の短い連絡・クロスポストであって、議論を求めた投稿ではない。**
**実質的にライセンスの議論を求めて返信がゼロだったのは、この 8 年で我々の 2 通だけである。**

**⚠ 何を establish しないか**: **理由は分からない。** 主題・時期・書き手・偶然のどれも排除できず、
**「substantive な提示で返信ゼロ」の n は 2 で、しかも 2 件とも同じ書き手である** ——
**「我々の投稿」と「この書き手」を分離できない。** 長さ・新参・時間帯では説明がつかない、
という**除外**までが、この測定の到達点である。

### 方法（再現できるように）

`https://lists.opensource.org/pipermail/license-discuss_lists.opensource.org/<YYYY>-<Month>.txt` を
ブラウザ相当の UA で取得（93 か月）。**encoded-word を復号してから**件名で正規化（`Re:` と
リスト接頭辞を剥がす）→ スレッド化。**事務連絡（`digest, vol` / `summary` 等）を除外**しないと、
返信ゼロの月次ダイジェストが長文バケットを汚染する（**初版はこれで「1000–1999 語は 41.7%」という
誤った谷を出した**）。

## 1.93 オーナーが挙げた 4 つの仮説を、掘ったコーパスに当てた（2026-09-17）—— 2 つは支持され、2 つは否定された

**2026-09-17、オーナーが沈黙の理由として 4 つ挙げた。**「測れる問いに散文で答えない」という
`REVIEWERS.md` の *check us* に従って、**4 つとも当てた。**

### (a)「前の 2 通は本文を読まないと答えられない形。今回は『何でも良いから意見を』だから反応が来やすい」→ **解像しなかった**

最初のメッセージ本文（8,000 字まで）を型で分けて返信率を測った:

| 型 | n | 返信あり |
| :-- | --: | --: |
| 条項を名指しして問う | 24 | 79.2% |
| どちらでもない | 275 | 73.1% |
| 広く意見を求める | 6 | 66.7% |

**方向はむしろ逆に見えるが、「広く意見を求める」は n=6 で、差は解像しない。**
**支持も否定もできない、が正しい答えである。** ただし ——**「条項を名指しして問う」形が
返信を減らしてはいない**ことは言える（79.2%）。**前の 2 通が「重い形だったから」返信が無かった、
という説明は、この窓では支えられない。**

### (b)「ディスカッションの方はそもそもやり取りの数が少ない」→ **支持される（ただし最近だけ）**

| 年 | `license-discuss` | `license-review` |
| --: | --: | --: |
| 2019 | **88.7 通/月** | 62.5 通/月 |
| 2023 | 7.9 | 13.1 |
| 2024 | 17.2 | 13.7 |
| 2025 | 15.1 | **29.4** |
| 2026（9 か月）| 11.4 | **33.7** |

**2025 以降、`license-review` は `license-discuss` の 2〜3 倍の流量を持つ。**
**ただし歴史的には逆で、2019 年の discuss は月 88.7 通あった** ——
**「discuss は元々静かな場所」ではなく、「discuss が静かになった」が正しい。**

### (c)「本申請と異なり、レビューする必要性が低い」→ **部分的に否定される**

**スレッドが立ったあとの挙動は、2 つのリストでほとんど変わらない**（2023 年以降）:

| | スレッド数 | 返信が付いた割合 | 1 スレッドあたり返信数 |
| :-- | --: | --: | --: |
| `license-discuss` | 86 | **79.1%** | 4.1 |
| `license-review` | 132 | **81.1%** | 5.0 |

**違うのは会話の数であって、会話する意欲ではない。**
**79% が返信を得る場所で、実質的な提示が 2 回連続でゼロなのは、やはり普通ではない。**

### (d)「申請者は企業単位、私は一個人」→ **否定される**

**フリーメール（＝個人）から始まったスレッドの方が、返信率が高い**（299 スレッド）:

| 開始者のアドレス | n | 返信あり |
| :-- | --: | --: |
| **フリーメール（gmail / icloud / proton / 163 等）** | 75 | **84.0%** |
| それ以外のドメイン | 224 | 69.2% |

**ライセンスを持ち込んだ個人は、軒並み返信を得ている**（`nik.sharky at gmail.com` の AI-MIT に 10 通 /
`lemonhub.io at icloud.com` の AGPL 議論に 11 通 / `amogusforever at protonmail.com` の
「新しいライセンスの出し方を教えて」に 5 通 / `anandchowdhary at gmail.com` の Twente License に 12 通 /
`van.lindberg at gmail.com` の CAL に 25 通）。

**⚠ 逆側**: 「それ以外のドメイン」は企業とは限らない（`cowan at ccil.org` / `tg at mirbsd.de` は個人ドメイン）。
そして**返信ゼロだった組織アドレス 4 件はすべて委員長の手続き連絡**であって、意見を求めた投稿ではない。
**つまりこの表が否定しているのは「個人だから無視される」であって、「企業だと有利」ではない。**

### 4 つを当てた結果として残るもの

**長さ・新参・個人であること・問いの重さ**は、**どれも我々の沈黙を説明しない。**
`license-discuss` の流量が落ちたことは事実だが、**それは「スレッドが少ない」ことであって
「立ったスレッドが無視される」ことではない。**

**説明が付かないという結果そのものが、今わかっていることである。**
**n=2 で書き手も同じなので、「この投稿」と「この書き手」を分離できない** ——
**次の 1 通が、その分離に使える唯一の実験になる。**
