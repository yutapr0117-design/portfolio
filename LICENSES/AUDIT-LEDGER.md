# 敵対的検証の台帳 —— OSI トラックで行った「全て」を、主張の種類ごとに潰す

**2026-09-14 にオーナーの依頼で開始**（*「既存の OSI 全振り自走で行った『全て』に対しての敵対的検証を
勧めます。『全て』の敵対的検証が一通り完了してから、次の何かに進むなら、異なる視点や観点も
見えてる状態になると思われます」*）。

## 0. この台帳の規律

**内容ごとに読まない。主張の*種類*ごとに機械化する**（#71 の掃引規律）。
内容で追うと「読んだところだけ」直り、読まなかった面は最初から射程に入らない。

**進捗は宣言せず導出する。** 各行の「母数 / 確認済み」は**道具を回して出た数**であり、
**手で更新しない**。今日 3 回、手で書いた状態宣言が古くなった実例が出ている
（`against.md` #140 / #141 / #142）——**この台帳自身がその class に落ちないため。**

**「未確認」は「誤り」ではない。** 分類してから結論する。**そして分類するまでは数を語らない。**

## 2. 種類 1 の結果（2026-09-14・第 1 回）

**母数 251 / 確認済み 156 / 未確認 95。** 手元の `rounds/` 26 件に加え、
**公開アーカイブ 49 か月**（`license-review` / `license-discuss`）を取得して照合した。

### 🟢 最も重い 5 件は、すべて逐語で一致した

| 引用 | 使われ方 | 結果 |
|---|---|---|
| Shuji Sado 氏 *"not open source, at least not in Japan"* | **提出文 §B.0 の gap 主張 2 本目**（§12 の存在理由）| ✅ 一致 |
| Pamela Chestek 氏 *"3888 words … excessively wordy and proscriptive"* | **B3（長さ）の根拠** | ✅ 一致 |
| 同 *"approximately 4500 words … I have not read these licenses in detail"* | 同上・2 例目 | ✅ 一致 |
| Rob Landley 氏 *"could you explain why you're doing another one?"* | **#84（なぜもう一つ PD 等価を）** | ✅ 一致 |
| Bruce Perens 氏 *"the proper language"* | **§8.1 の語が受け入れられた形だという主張** | ✅ 一致 |

**誤引用は 1 件も出ていない。** ただし **251 件中 156 件を確認した段階の話**であり、
**「誤引用は無い」ではなく「確認した範囲で誤引用は無い」**である。

### 🔴 構造的な発見 —— 我々は、手元に持っていない source を引いている

**帰属つき引用 251 件のうち、`rounds/` の一次資料だけで確認できたのは 52 件。**
残りはアーカイブを取得して初めて照合できた。**つまりドシエの証拠の大半は、
リポジトリの外に在る。**

**これは #92 が 1 度指摘して 8 件だけ直した問題の、一般形である**
（*「分析だけがあり、依拠する原文はリポジトリに無かった」*）。
**規律は「受領文を保存する」と書いてあり、受領していない引用は射程外だった** ——
**だが審査者から見れば、受領文かどうかは関係がない。引用は引用である。**

**⚠ ただし逆側**: **アーカイブ全月を `rounds/` へ入れるのは誤り。**
49 か月で 7 MB あり、**無改変保存のディレクトリを「読んだものの置き場」に変えると、
`rounds/` が「相手が我々に何を言ったか」の記録である性質が壊れる**（Check 465 の在庫申告も無意味になる）。
**採った形**: **道具を committed にし、誰でも再現できるようにした。**
**証拠を持つのではなく、証拠への到達手順を持つ。**

### ⚠ 検出器を 3 回作り直した（母数 4,976 → 495 → 251）

初版は「引用らしき文字列」を **4,976 件**と数えた。**大半は markdown の太字記法**だった。
ドシエの規約 `*"..."*` に絞って **495**、人名の近傍に絞って **251**。
**母数が大きすぎるときは、母数の作り方が間違っている** —— 道具の履歴を script の docstring に残した。

### 未確認 95 件の性質（**分類してから数える**）

抽出した 95 件には**我々自身の文を強調で括ったもの**が混じる
（例: *"the heaviest finding of this session"* / *"grep once before writing it"*）。
**これらは外部引用ではないので「未確認」の母数に入れるべきではない。**
**次回はまず (a) 我々の文 (b) 未取得の月 (c) 真に照合できないもの に分ける。**
**(c) が出たときだけが問題である。**

## 4. 種類 4 の結果（2026-09-14・第 1 回）—— 自動照合は原理的にできないと分かった

**母数 233**（`LICENSES/*.md` の「0 件 / ゼロ / 一度も / どこにも無い / 存在しない / 先例が無い」型。
引用行は除外 ——引用は我々の主張ではない）。

### 🔴 いちばん重い発見は、ドシエではなく方法について出た

**不在の主張は、母集団を名指ししていなければ検証できない。**
自動照合を書いて走らせたら **約 30 件が「反証された」と出たが、全部が偽陽性だった** ——
検出器が「`X` は 0 件」の `X` を `LICENSES/` 全体で grep したのに対し、
**実際の主張の母集団は、ある時はライセンス本文、ある時は承認済み 149 本、
ある時はアーカイブの特定の月、ある時は過去のある時点**だった。

**測ると、母集団か道具を同じ行に持つ不在主張は 233 件中 49 件（21%）。**
**⚠ ただしこの 21% を「79% が欠陥」と読んではいけない** ——
*"no court has tested it"* のような**質的な不在**は、そもそも grep で確かめる種類ではない。
**分けずに数えたので、この数は上限の側に外れている。**

**規律として出るもの**: #87 は「数を報告するときは、その数を作った道具も同じ場所に書く」と述べた。
**ゼロにも同じことが要る** ——**そしてゼロは、我々がいちばん多く間違えてきた数である**
（#87 / #88 / #92 / 本日の `widest permission`）。
