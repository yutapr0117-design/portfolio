<div dir="ltr">Hello,<br><br>I would like to get feedback on a new license before any formal submission. This is about the Model Chain Attribution License (MCAL), which is not a modification of any existing license but a new license designed for a specific, measurable problem in the AI supply chain.<br><br>The problem is what a 2026 study calls &quot;permissive washing.&quot; The study audited 294,012 dataset -&gt; model -&gt; application supply chains and found that 96.9% of datasets and 96.4% of models lack the required license text, even when labeled MIT or Apache-2.0. More importantly, attribution collapses as artifacts move downstream: only 25.0% of models preserve compliant dataset notices, and only 5.4% of applications preserve compliant model notices.<br><br>This means that even when upstream components have permissive licenses, the legal basis for using them is often lost by the time they reach an application. Companies using these models may be operating outside the scope of the original license without knowing it.<br><br>The MCAL proposes a different mechanism to address this. Instead of requiring a license file or a copyright notice in every artifact, it requires a structured, machine-readable Attribution Record. This is a single, extensible JSON, YAML, or XML file that lists the artifact&#39;s upstream dependencies, their licenses, and their relationship types (e.g., &quot;trained-on&quot;, &quot;derived-from&quot;). The record propagates automatically through the chain: from dataset to model to application.<br><br>The core question is: is this a real problem that a license can address? And if so, is a machine-readable attribution record the right mechanism?<br><br>I have attached the full text for context. I would appreciate any feedback, especially on:<br>1. Whether this problem is worth solving at the license level.<br>2. Whether the proposed mechanism is feasible and clear.<br>3. Whether there are any OSD concerns I should be aware of.<br><br>Thank
