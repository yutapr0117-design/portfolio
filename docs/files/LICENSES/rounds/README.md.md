# LICENSES/rounds/README.md

## What

OSI のメーリングリストから受け取った本文を、**無改変で**置くディレクトリの規約。1 ラウンド
1 ファイル（`<round>-<venue>-raw.md`）で、置き方・してはいけないこと・いまの状態を述べる。

## Why

`REVISION-PROTOCOL.md` は 3 箇所（§0 の英文コミットメント / §1 の「① 受領」/ §3 のゲート 1）で
このディレクトリを指しているのに、**2026-09-06 まで実体が無かった**。公開している約束が指す先が
存在しない状態で、審査者が数秒で確かめられる乖離だった。**返信が来てから作ると、いちばん急いで
いるときに置き方を決めることになる**ので、先に作った。

分析と原文を**物理的に分ける**ことが要点である。こちらの読みは誤りうるが、**何と言われたかの
記録は誤ってはならない**。

## How

- 受領文は無改変（整形・要約・翻訳・並べ替え・typo 修正すべて不可）
- 分解・分類・応答は `ACD-1.0.discussion-log.md` 側
- 先頭に最小限のヘッダ（日付 / venue / 受け取り方）のみ可。本文との境界が分かる形にする
- 個人名を推測で足さない。公開アーカイブに現れるとおりに引く

## Constraints

- **空であること自体は記録にならない。** 「届いていない」のか「置き忘れた」のかは区別できないので、
  区別は `discussion-log.md` §2.5 の日付つき記録が担う（`REVISION-PROTOCOL.md` §3.5）。
- `LICENSES/*.md` の glob は非再帰なので、本 file は Check 459（索引到達性）や 461c（last-updated）の
  対象外である。到達性は `LICENSES/README.md` の表からのリンクで担保している。

## Change impact

ラウンドが実際に始まったら、ここに raw file が増える。**そのとき §3 のゲート 1（受領全文が
`rounds/` に無改変で入っている）が初めて検証可能になる**。

## Audience-specific notes

- **監査人**: 原文と分析が別 file にあることが、要約の正しさを後から確かめられる唯一の条件である。
- **第三者**: メーリングリストのアーカイブは公開されているので、ここの内容は原文と照合できる。
