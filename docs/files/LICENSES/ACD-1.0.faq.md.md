# LICENSES/ACD-1.0.faq.md

## What

**レビュアではなく「実際に使うかもしれない人」の疑問**に答える FAQ。3 部構成。

- **A. 使う側**（12 問）: 適用の仕方 / 帰属表示 / 改変再配布 / 用途制限 / GPL・Apache との組み合わせ（**逆向きは別の話**）/ 特許を持っている場合 / データ・モデル / 学習と出力 / 作者の死亡・破産 / **SPDX 未登録時の表記** / **依存スキャナが未知と言う場合** / 法務への説明材料
- **B. プロセス**（5 問）: 現在の段階 / 却下や無反応 / SPDX の時期 / 1.1 の作り方 / 連絡先
- **C. リポジトリのどこを見れば何が分かるか**（逆引き 11 行）

## Why

想定問答・逐条・族比較・法域はいずれも**審査を受ける側の視点**で書かれている。だが「疑問が全てリポジトリを見たら潰せるように」という目標には、**使う側の実務**が要る。

とくに次の 2 問は、他のどの文書にも答えが無かった。

1. **SPDX 識別子が無い状態でツールにどう書くか** ―― 未登録なので `LicenseRef-ACD-1.0` として全文を添えるのが標準的な扱いになる。§16.1 の通知が `SPDX-License-Identifier: ACD-1.0` を含むのは**登録の主張ではなく通知の様式**（§16.2）だという説明も要る。
2. **依存関係スキャナが「未知のライセンス」と言う** ―― 想定内である。手動登録 / ポリシー上の分類へマップ / **判断できないなら使わない**（これは正当な選択であり、こちらから止める理由は無い）。

## How

- 各問に「そのまま貼れる英文」＋日本語の補足。
- **A12（法務への説明材料）は表で場所を示し、最後に「弱点の場所を先に示すこと」と書いた** ―― 法務が自分で見つけると、その後の説明が全部疑われるため。
- **C の逆引き表**が「疑問 → 見る場所」の入口。**ここに無い疑問が出たら、それはこの一覧の欠落である**と明記した。

## Constraints

- **非規範。** 法的助言ではない。齟齬があれば本文が勝つ。
- **B1（現在の段階）は `FROZEN.md` の `VENUE-DATA` を単一ソースとして参照する**。ここに venue を直書きすると Check 458 が守っている整合が壊れる。
- 本書を根拠に `ACD-1.0.txt` を編集してはならない（Check 453）。

## Change impact

- 実際に質問が来たら追記する。**C の逆引き表も同時に更新すること**（入口が古いと本文が増えても届かない）。
- SPDX へ登録された時点で A10 / A11 / B3 は書き換えが必要になる。

## Audience-specific notes

### For AI agents（次担当）

- 役割タグ: `license`, `faq`, `adopter-facing`, `spdx-licenseref`, `non-normative`
- **A11 の 3 番目の選択肢（判断できないなら使わない）を削らないこと。** 採用を勧めない選択肢を自分から書いているのが本書の姿勢であり、`comparison.md` §6（条件が合うなら 0BSD を薦める）と一貫している。
- B1 は venue を直書きしない。**単一ソースは `FROZEN.md`**。

### For human engineers（新卒レベル）

ライセンスの文書は普通「審査する人」向けに書かれるが、実際に困るのは**使う人**である ―― 「帰属表示は要るのか」「うちのスキャナが読めない」「法務に何を見せればいいのか」。この FAQ はその層に答えるもので、**答えが「使わないほうがよい」になる場合もそう書いてある**。

### For third parties / auditors

本書は採用を勧めていない。A6（特許を持っているなら適用するな）、A11（判断できないなら使うな）、B2（撤回条件を事前に公開）はいずれも**採用者を減らす方向の記述**である。監査上は、この姿勢が `comparison.md` §6 および `review-responses.md` Q1 と一貫していることを見ればよい。
