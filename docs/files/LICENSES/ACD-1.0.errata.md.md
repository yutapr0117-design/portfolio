# LICENSES/ACD-1.0.errata.md

## What

本文に見つかった**不正確さ 5 件**（E1〜E5）と、**そのどれも直していない理由**、そして
1.1 で何をするかを 1 箇所に集めた英語の文書。severity 順ではなく条ごとに並べ、
「利用者にできることを変える欠陥は 1 件も無い」ことを明示する。

## Why

欠陥の指摘は `against.md` に散在していた（#18 / #20 / #22 / #27 / #21）。散っていると
**こちらが把握していないように見える**し、1.1 を書く人が拾い集める作業を負う。集約して
公開することで、「凍結中だから直さない」が**言い訳ではなく規律**であることを具体で示せる。

E1（§16.1 が未登録の SPDX 識別子を書けと指示している）は**読み手に誤った行動を指示する
唯一の箇所**なので最優先と明記した。

## How

各行に「何が不正確か / 1.1 で何をするか / severity」を書く。凍結の検証コマンド
（`shasum -a 256 -c`）を冒頭に置き、**信用ではなく実行で確かめられる**ようにする。
末尾に凍結解除時の手順（E1 を最初に / §4c の全性質を再測定 / digest 再生成 /
discussion-log にどの指摘がどの変更を導いたか記録）を固定した。

## Constraints

- **ライセンス本文は凍結中**（Check 453 が 3 件の sha256 を pin）。本書は本文に触れない。
- 新しい欠陥が見つかったら**まずここへ足す**。反論して消すのではなく行を残す。
- 「利用者にできることを変える欠陥」が出た場合は、修正ではなく**撤回**が正しい応答で
  ありうる（submission §E.2 / against.md と同じ条件）。

## Change impact

凍結が解けたら本書の手順に従い、E1 から順に適用して `FROZEN.md` の digest を再生成する。
その際 `submission.md` §4c の測定値も再測定する（一度検証した性質は、そのまま真であり
続ける性質ではない）。

## Audience-specific notes

- **審査者**: 6 件目を見つけたら、それは**我々のレビューの失敗**であって指摘の側の失敗では
  ない、と本文に書いてある。
- **監査人**: 「直せない期間に見つけた欠陥をどう扱うか」の実例。隠す・こっそり直す・
  公開して残す、の 3 択で 3 番目を取っている。
