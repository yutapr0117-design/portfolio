# LICENSES/ACD-1.0.review-corpus.md

## What

**OSI の 2 つのメーリングリストのアーカイブを全部取得して、数えた結果を置く file。**
`license-review` **2024-01〜2026-09（33 か月・804 通・111 スレッド）**と
`license-discuss` **同期間（443 通・30 か月分。3 か月は投稿ゼロ）**が対象である。

収めているもの（§1.67 以降）——**承認の基準 8 条**（原典の "Standard for new licenses"）/
**委員会が実際に述べた「承認しない／受け入れる」規則**/ **決議の分布**（承認 4・否決 8・
「新規ではない」1）/ **否決理由の 2 つの束** / **提出から理事会の決定までの実測所要**（中央値 101 日）/
**`license-discuss` を先に通す率**（20 件中 5 件）/ **手続きの不備で止まっている実例** /
**要件リストと我々の文面の 1 項目ずつの突合**。

## Why

**`ACD-1.0.review-precedents.md` から 2026-09-13 に切り出した。分けた理由は行数ではなく種類である。**

- `review-precedents.md` = **個別スレッドを読んで得た指摘**（＝**読み**）
- 本 file = **アーカイブ全体を取得して数えたこと**（＝**測定**）

**この区別には根拠がある。** `against.md` #131 に記録したとおり、**このドシエの「読み」を書いて
いるのは振れる 1 体の agent** であり、**読み手には「測定を読みに優先せよ」と伝えてある。**
**その 2 つが同じ file に混ざっていると、優先のしようがない。**

**切り出しの直接の引き金は Check 365（1,000 行 BLOCKING）だった** ——**advisory (900) を
越えたのに先回りできず、BLOCKING を踏んでから動いた**（同じ後退を過去にもしている）。
**対処は圧縮ではなくテーマ分割**、という規約どおりに処理した。

## How

**節番号は動かしていない。** §1.67 は §1.67 のまま本 file にある ——
**既存の参照をすべて有効に保つため**で、`comparison.md` → `review-precedents.md` の分割と同じ規約。
移動に伴い、**移動した節を指す参照 7 file を機械的に retarget した**（節番号ではなく file 名だけを差し替え）。

**新しい節をどちらに足すかの規則**: **個別スレッドの読み → `review-precedents.md` /
アーカイブ全体の測定 → 本 file。**

## Constraints

- **測定には instrument を併記する。** どの月を取り、どう分割し、何を数えたかを節ごとに書く
  （#87 —— 数を報告するときは、その数を作った道具も同じ場所に書く）。
- **折り返しヘッダは展開してから解析する**（#99）。
- **名称一致で数えたものは floor だと明記する** —— §1.71 は実例で外している（OSC License）。
- **予算 advisory 900 / BLOCKING 1,000**（Check 52 / 365）。越えたら**圧縮ではなくテーマ分割**。

## Change impact

本 file を消すと、`ACD-OSI-BOTTLENECKS.md` の冒頭節（2026-09-11 の掘削結果 8 点）と
`AS-OF.md` の複数行が**根拠を失う**。節番号を変えると、**7 file の参照が解決しなくなる**
（Check 460 の `#N`・`§N` 解決性が検出する）。
