# LICENSES/ACD-1.1-SELF-AUDIT.md

## What

**草案を我々自身が掃引して出たものの記録。** 2 系統ある ——
**(a) 草案の改訂が作った欠陥**（1.0 には無い）と、
**(b) 既に直したはずの形を、直していない条の集合へ当て直して出たもの**。

## Why

**errata は 1.0 の欠陥の登録簿である。** そこへ「1.0 には無く草案が作った欠陥」を混ぜると、
errata が述べている「すべて 1.0 で未修理」という性質が偽になる。**`E<n>` は 1.0 を指す記法**なので、
同じ記法に 2 つの採番体系を同居させると、審査者は存在しない事実を探すことになる。

**そして、この記録が無いと同じ欠陥が繰り返される。** 実際に出たものは
**直前の改訂が作ったもの**だった —— E17 が §5.3 に限定を足したとき §4.6 の要約を見ていない、
E14 が制限を族へ広げたとき自分の次版を締め出した。

## How

- **掃引の単位はレンズごとに違う。** 「この版で変えた条項」（その条項を引用・要約している他の条項を
  全部当てる）／「許諾文」（① 権利主体 ② 権利範囲 ③ 第三者権利との境界 を本文単独で持つか）——
  **どちらも 1 条ではなく集合に当てる**
- **判定の規則を先に書く。** 書かないと「限定を全条に足す」へ流れ、それは padding で
  **B3（長さ）を悪化させるだけ**である
- **clean も必ず書き残す** —— 1 件を狙って当てたのではなく、全件に当てて 1 件だけ落ちたことを示す
- **番号は振らない** —— `E<n>` は 1.0 用。ここは節（§3e / §3f）で指す

## Constraints

- **1.0 の本文・`spdx.xml`・`machine.json` は編集しない**（Check 453 が sha256 で止める）
- 草案の語数・条数の申告は **Check 468** が実測と照合する（本文を触ったら申告も直す）
- Check 459 が索引（`LICENSES/README.md`）からの到達性を、Check 461c が `last-updated` を強制

## Change impact

**草案の条文を変えたら、この file の掃引をやり直す。** 出たものの多くは
**直前の改訂が作ったもの**だった ——**一度掃いても、次の改訂が次の stale を作る。**

## Audience-specific notes

- **審査者**: 「自分の改訂が何を壊したか」をこちらから先に出している面である。
  **1.0 の本文はこの file の存在によって一切変わらない**
- **後任 AI**: 新しい発見をここへ足す前に、それが **1.0 にも在る欠陥**かを確かめよ。
  在るなら errata（`E<n>`）で、草案だけなら ここ
