# LICENSES/ACD-OSI-BOTTLENECKS.md

## What

**OSI 承認を阻害する要因の canonical な一覧。** 13 項目を 12 の解消可能性クラスへ分類し、
重大度・status・人間 / 弁護士 / OSI のいずれを要するかを表にする。
上位項目（B3 長さ / B4 献呈と許諾の並存 / B10 gap / B12 steward）は
**問題 → なぜ承認上の問題か → 最小の解消方法 → 失うもの → 残る gap → 副作用 → 外部確認の要否**
まで節で書く。

## Why

**目的が「欠陥を数えること」から「承認阻害要因を除去すること」へ変わったため。**
`against.md` の不利な事実（117 件）は**入力**であって、そのすべてが承認のボトルネックではない。
**1 件の構造的問題は 100 件の軽微 errata より重い**ので、
**class 11（解消方法不明）と class 12（構造的両立不能）を最優先で探す**枠が要る。

**単一の canonical 一覧である理由**: 同じ問題を複数の文書で独立に管理すると、
片方だけが更新されて drift する（このリポジトリが繰り返し記録してきた失敗）。

## How

- **2026-09-09 に現物と一次資料から再構築した**（既存の一覧を鵜呑みにしない）
- **B3 は測定で解消経路を出した** —— 本体 4,574 語のうち gap 部は 23%、machinery 部が 44%。
  **削減候補 ≈529 語はすべて machinery 側**で、gap には 1 語も触れない
- **B4 は class 12 候補として検証し、否定した** —— 委員長の批判の実体は並置ではなく
  「全部放棄と言いながら個別に留保する」ことで、挙げられた 4 留保のうち ACD に在るのは 1 つ

## Constraints

- **本文は凍結中。** ここに書かれた解消方法は **successor candidate** であって、
  1.0 へ適用しない
- **class 12 と断定するには**、一次情報・論理経路・代替設計・縮小案・削除案・構造変更案まで
  検討してからにする（B4 はその手順で否定した）
- **削って gap が消えたら失敗**である（B10 が gap を担う 3 条項を特定している）

## Change impact

新しい問題は必ずこの表へ入れて分類する。分類が付かないものは `against.md` に留める。
**revision ごとに集計（主要 / 解消済み / 新規 / OSI 依存 / 弁護士待ち / 方法不明 /
構造的拒否候補）を比較し、減っていなければ revision 自体を疑う。**

## Audience-specific notes

- **審査者**: 我々が自分の障害を分類し、どれが自力で解けてどれが OSI 判断依存かを
  区別していることの記録
- **後任 AI**: **ここから始める。** 最も承認確率への影響が大きく、かつ AI だけで前進できる
  未解消項目は **B3** である（測定と削減候補が揃っている）
