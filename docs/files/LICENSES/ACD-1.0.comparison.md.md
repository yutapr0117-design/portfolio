# LICENSES/ACD-1.0.comparison.md

## What

「**X で足りるのでは**」への答えを**ライセンス族ごと**に置く文書。既存の比較（`acd-license-rationale.md` §2 の無条件系 6 列比較と 0BSD / Apache-2.0 の逐条差分）が扱っていない **4 族**を補う。

1. **copyleft 系**（GPL / AGPL / LGPL / MPL / EUPL）
2. **AI 用途制限系**（RAIL / OpenRAIL / Llama / Gemma / BigScience）
3. **source-available 系**（BUSL / SSPL / Elastic / PolyForm）
4. **データ系**（ODbL / CDLA / PDDL / CC-BY-SA）

加えて、読み手が自分で当てはめられる **3 つの判断基準**と、**意図的に扱っていないもの**の一覧。

## Why

「なぜ新しいライセンスが要るのか」への答えは、**相手がどの族を念頭に置いているかで変わる**。同じ答えを繰り返すと噛み合わない。

とくに **AI 用途制限系との混同**は放置できない。近年「AI に言及するライセンス」の大半は**制限**であり、レビュアはその前提で読み始める。ACD-1.0 は**方向が逆**（許諾）なので、表面の類似が反転を隠している。この誤読は OSD 6 の議論全体を汚染しうる。

**copyleft は価値観の問い**で、技術的に答えると衝突する。「あなたの選択が誤りだとは言っていない。この作品には合わないだけだ」と述べ、**失うもの（還元されない）を自分から認める**のが唯一噛み合う形。

## How

- 各族に「そのまま貼れる英文」＋「なぜこう答えるか（日本語）」。
- **§6 の判断基準が本書で最も重要**: 条件を求めるなら使うな / 用途を制限したいなら使うな / 特許を出したくないなら使うな。そして **3 つとも「no」でソフトウェアだけなら 0BSD を薦める**と書いてある。

## Constraints

- **非規範。** 齟齬があれば本文が勝つ。
- **他ライセンスの条文を引用しない。** 引用は誤りが混入しやすく、本書の主張は**構造の違い**にあって字句の差ではない（その旨を §7 に明記）。
- **OSI 承認の一覧を写さない。** 時点依存で腐る。一次資料は OSI の公開ページ。

## Change impact

- 新しい族（例: 新種のモデルライセンス）が問われたら節を足す。
- **§6 で「0BSD を薦める」と書けることが proliferation 指摘への最も強い姿勢**なので、この節を弱めない。

## Audience-specific notes

### For AI agents（次担当）

- 役割タグ: `license`, `comparison`, `license-families`, `non-normative`
- **他ライセンスの詳細を断定で足さないこと。** 本書は構造の違いだけを述べる設計で、字句や版差に踏み込むと誤りが混入する（`review-responses-meta.md` Q10 が警告する「捏造・誤帰属の権威引用」と同じ risk）。
- 「扱っていないもの」の表を消さない。**抜けではなく判断であることを示すため**に在る。

### For human engineers（新卒レベル）

「似たライセンスがあるのに、なぜ新しく作ったのか」は必ず訊かれる。相手が思い浮かべているライセンスによって、答えるべき内容が変わる ―― 共有を求める種類のものを思い浮かべている人には「共有を求めない理由」を、AI を制限する種類のものを思い浮かべている人には「これは逆向きだ」を答える必要がある。

### For third parties / auditors

本書は**自分のライセンスを薦めていない**。§6 は 3 つの判断基準を示し、**条件が合うなら 0BSD を使えと明記**している。監査上は、この姿勢が `review-responses.md` Q1（「既存で埋まるなら撤回する」）と一貫していることを見ればよい。
