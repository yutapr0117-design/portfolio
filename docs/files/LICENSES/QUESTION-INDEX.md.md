# LICENSES/QUESTION-INDEX.md

## What

**疑問の側から引く索引。** ドシエには 118 の worked entry（4,185 行）があるが、既存の索引
（`LICENSES/README.md`）は**文書名**で並んでおり、「この疑問はどこに答えがあるか」で引けない。
本書は 7 分類（最初に来る問い / 適合性 / 本文そのもの / ML・TDM・特許・データ / 法域と効力 /
使い方 / 手続き）で、質問 → 答えの所在、という形に並べ替える。

## Why

**量を増やすことと、往復を減らすことは同じではない。** 4,185 行あっても、審査者が探せ
なければ質問は来る。来た質問に「それは §X に書いてあります」と答えるのは、**相手の時間を
使わせた後に案内している**ことになり、往復を減らす効果が薄い。

狙いは「**リポジトリを見れば分かる**」を成立させること —— そのためには**答えが在ること**
ではなく**答えに届くこと**が要る。だから新しい答えを増やすのではなく、既にある 118 件への
経路を作った。

**答えを繰り返さない**のも意図的である。本書は所在だけを示し、内容は各文書に置く
（重複させると片方だけ古くなる —— このリポジトリが繰り返し踏んできた drift）。

## How

各行は「審査者が実際に持つであろう疑問」を主語にする。**不利な答えも同じ表に並べる** ——
「弁護士は読んだか → **No**」「採用は何件か → **1 件**」のように、答えを行内に書いてから
所在を示す。探させてから不利な事実に出会わせるのではなく、**索引の時点で分かる**ようにする。

## Constraints

- **ライセンス本文は凍結中**（Check 453）。本書は所在を示すだけで本文に触れない。
- 索引掲載は Check 459 が BLOCKING で強制。
- ドシエに項目が増えたら本書にも行を足す。**指す先が無い行を残さない**（`against.md` の
  番号は増えるので、番号で指す行は特に注意）。

## Change impact

新しい worked entry を足したら、本書へ 1 行足すかを判断する。**全部を索引に載せる必要は
ない** —— 載せるのは「審査者が疑問として持つ形」のものだけで、内部向けの記録は対象外。

## Audience-specific notes

- **審査者**: 「ここに無い疑問があれば、それは我々の omission なので list で言ってほしい」と
  本文に書いてある。
- **監査人**: 情報が在ることと届くことを分けて扱った例。量の追加ではなく経路の追加で解いている。
