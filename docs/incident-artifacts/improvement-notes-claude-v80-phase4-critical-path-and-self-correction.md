## 主要な成果

### 🟢 #1239 quiz データ 130,595 bytes をクリティカルパスから外す

`js/quiz/*.js` は **配信 JS+CSS の 15.6%** を占め、main.js が静的 import し
**modulepreload まで宣言**していた。つまり **quiz を一度も開かない訪問者も毎回 4 ファイル
すべてを高優先度で取得**していた (実測: home 表示だけで 4 件 fetch)。

動的 import へ移し、home では 0 件・quiz を開くと該当 1 件だけになった。

**設計の要点**: レンダリング switch は同期 (`page = QuizPage()`) なので **render core は触らない**。
QuizPage が容器を同期返却し、データ到着後に `listHost` だけ差し替える (ProjectsPage と同じ
house pattern)。`_filterBy` はデータ未着を空集合として扱う総関数にした (throw すると FatalPage)。

**Check 120 が測る対象も是正した (本 run の中核)**: 宣言された目的は「実 download/parse 負荷の
保護」だが、実装は **ディスク上の全 shipped ファイル**を足していた。したがって遅延化しても
数字は減らず、むしろ loader の分だけ**増えた**。それでは「上げるか削るか」の判断材料に
ならない。静的 import 分だけを数える形へ (除外集合は main.js から導出＝次の遅延化にも自動追従)。

    840,932 → 710,337 bytes (−15.5%)

本セッションで 4 回ラチェットアップ (837,000 → 838,600) していたが、**初のラチェットダウン**
(→ 715,000) で元より 12 万バイト以上軽くなった。

**追随させた Check 5 件** (綴りが増えただけで invariant は不変):
47b (動的 import も消費として数える) / 57 (遅延モジュールは modulepreload 対象外) /
401・435 (`QUIZ_DATA_MAP` → `QUIZ_TITLES`) / 362 (orphan anchor 4 件)。

### 🔴 遅延化が持ち込んだ欠陥を 4 つ、自分で見つけて直した

  #1240 読み込み中が SR に伝わらない        → `aria-busy` を listHost にも
  #1241 読み込み失敗が未テスト              → 失敗経路を BLOCKING e2e で固定
  #1243 読み込み中に入力した検索語が捨てられる → 到着時点の入力値で描く
  #1243 未着を「見つかりませんでした」と偽る  → 読み込み中は読み込み中として見せ続ける

とくに #1243 の 2 件は「見出しと検索欄を同期に描く」設計から自然に生まれた race で、
**遅延化を入れた本人が探さないと誰も踏まない**面だった。

### 🔴 同じ assertion で 3 回 vacuous を踏んだ (#1239 → #1240 → #1242)

「データが届いた」ことの検証で:

    1 回目 `.card`              → **「問題を読み込んでいます…」のボックス自体が .card**
    2 回目 `#content h2`        → **問い合わせ見出し「模範解答について」が同期描画される**
    3 回目 `[data-quiz-list] h2` → 正しい (データ取得を abort すると 0 件 = RED)

**教訓: 「vacuous を直した」と言う前に、直した後のセレクタで RED を実測せよ。**
1 回目も 2 回目も「それらしいが同期描画される要素」に一致していた。
契約フックは class でなく data 属性にする (#929 の規律)。

前 run 終了時点で canon がちょうど 1,000 行に達し、**次のセッションが Session Record を

全体を表す」という解釈が誤りで **Check が権威**だった。元へ戻し、
「AIO 層が宣言する archive 範囲は #14 まで」という**未解決を明記**した (埋めるには C6 承認が要る)。

  BGM ボタンの sr-only は **aria-label が上書きするので一度も読まれず**、しかも同期対象外で
  再生中も「再生する」のままだった (latent trap: aria-label を消すと名前が永久に固定)。

## 教訓

- **その gate は実際に何を測っているのか。** Check 120 は「download/parse 負荷」を名乗りながら
  ディスク上の全ファイルを足していた。遅延化という**正しい改善で数字が悪化する**gate は、
  改善の方向を誤らせる。
- **「vacuous を直した」と言う前に RED を実測せよ** (3 回踏んだ)。
- **自分が入れた変更は、自分で探さないと誰も踏まない面を作る。** 遅延化は「データが来るまでの
  窓」という**新しい状態**を作り、そこに 4 つの欠陥があった。
- **条件が意図せず先に成立する class を 5 回踏んだ。** `.card` / `#content h2` /
  `[data-quiz-loading]` の消失 (入力すると作り直される) / 再訪しても検索語が永続 (#684) /
  `aria-busy='false'` が前の描画で満たされる。**待ち条件は「その変化だけが起こす状態」を選べ。**
- **測定系を疑う (本 run でも 2 回当たった)。** `fill()` の 19 秒 / 「sidebar だけラベルが
  更新されない」と誤読 (textContent と aria-label の混同)。
- **advisory は BLOCKING の手前で効かせる。** mutation ログの rotate で **2 度後退した**
  (#1233 / #1240)。advisory (975) を跨いだ時点で処理すること。
